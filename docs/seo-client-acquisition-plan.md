# SEO и органическое привлечение клиентов: рабочий план «Согласовано»

Обновлено: 10 октября 2026 года.

## Цель и критерий завершения

SEO не считается выполненным по факту публикации страниц, роста показов или попадания отдельных запросов в топ. Цель достигнута только когда одновременно выполняются два условия:

1. есть подтверждённые доставленные заявки из органического поиска с сохранённой атрибуцией;
2. согласованный коммерческий кластер удерживается в топ-10 целевого региона не менее 28 дней.

Промежуточные метрики: индексируемые страницы, небрендовые показы, клики, CTR, позиции по паре «запрос → страница», переходы к кейсам, начало формы и подтверждённая доставка.

## Текущее состояние: без скидок

### Что технически сделано хорошо

- Production, HTTPS, canonical-host, `www`-редирект, robots и sitemap работают.
- Неизвестные URL и неизвестные кейсы возвращают настоящий 404, а не soft 404.
- В sitemap 98 уникальных канонических страниц; локальная проверка подтверждает уникальные title, description, canonical и H1.
- Кейсы имеют статический HTML, метаданные и schema без зависимости от клиентского JavaScript.
- Форма передаёт UTM, внешний referrer, поисковик и канал `organic_search`; успешное событие возможно только после ответа backend.
- Созданы отдельные коммерческие страницы под B2B, промышленный UX/UI, гостиницы, туризм, финтех и мобильные приложения.
- Десять сильных кейсов связаны с релевантными коммерческими страницами и атрибутированными формами.
- Генератор кейсов теперь хранит SEO-заголовки и service-path в manifest; проверка падает, если очередная сборка их удаляет.

### Почему потока клиентов пока нет

1. **Нет доказанного измерительного контура.** По последним доступным данным Google Search Console не настроена, Метрика не связана с Яндекс Вебмастером, а подтверждённых органических лидов нет. Без данных нельзя отличить отсутствие спроса от проблем индексации, сниппета или конверсии.
2. **Сайт только начал покрывать коммерческие интенты.** Большая часть старого контента информационная или портфолийная. Новые service-pages ещё должны быть проиндексированы и накопить историю.
3. **Слабая внешняя авторитетность.** Технически правильный сайт без упоминаний и ссылок редко конкурирует по коммерческим запросам с агентствами, каталогами и крупными студиями.
4. **Недостаточно доказательств на части коммерческих маршрутов.** Сильные кейсы есть, но не для каждой аудитории зафиксированы исходная бизнес-задача, подтверждённый результат, роль студии и следующий шаг.
5. **Нет регулярного процесса спрос → страница → доказательство → лид.** Разовые SEO-правки не создают поток. Нужен недельный цикл: данные, одна гипотеза, изменение, проверка, аннотация, оценка.
6. **Нет подтверждённого end-to-end теста доставки лида из production.** Health-check подтверждает конфигурацию endpoint, но не доказывает получение реального сообщения владельцем. Тестовая заявка допустима только с явным разрешением владельца.
7. **Географические дубли не решат проблему.** Пятнадцать копий главной с заменой города будут doorway-страницами: одинаковый смысл, отсутствие локальных доказательств и высокий риск каннибализации. Городская страница допустима только при уникальном предложении, локальном спросе, кейсе/отзыве/условиях работы и самостоятельной ценности.

## Приоритет 0: измерение и доставка лидов — 1–3 дня

Готово, когда данные GSC доступны и sitemap имеет статус Success. Изменения аккаунта выполняются владельцем или с отдельным разрешением.

### 0.2 Яндекс Вебмастер и Метрика

- Связать счётчик `110947439` с Вебмастером.

- Создать сегмент «Переходы из поисковых систем» без брендовых запросов, где данные доступны.

### 0.3 Подтверждённая доставка

Для каждого события: landing page, service, source, medium, campaign, referrer, search engine, device class.

## Приоритет 1: индексация и коммерческие кластеры — неделя 1–2

### 1.1 Проверить индекс по каждой целевой странице

Отдельно для Google и Яндекса проверить:

- `/landing-page`
- `/site-redesign`
- `/ux-ui-design`
- `/b2b-corporate-website`
- `/industrial-interface-design`
- `/hotel-website-development`
- `/travel-company-website`
- `/fintech-interface-design`
- `/mobile-app-design`

Не создавать новые страницы, пока не понятен статус этих URL. Для исключённых страниц фиксировать конкретную причину: discovered, crawled, duplicate, canonical mismatch, soft 404 или quality.

### 1.2 Карта запросов

Для каждого кластера выбрать одну основную страницу и исключить конкуренцию собственных URL. Минимальная карта:

| Кластер | Целевая страница | Основное доказательство |
|---|---|---|
| создание лендинга | `/landing-page` | релевантные сайты и прозрачный состав этапа |
| редизайн сайта | `/site-redesign` | кейсы до/после и UX-аудит |
| UX/UI SaaS | `/ux-ui-design` | MIROX, VISI FLOW, Octoclick |
| корпоративный B2B-сайт | `/b2b-corporate-website` | Пифагор, ВебОценщик |
| промышленный интерфейс / HMI | `/industrial-interface-design` | WEINTEK PANEL |
| сайт отеля | `/hotel-website-development` | Diplomat Hotel |
| сайт туроператора | `/travel-company-website` | LEKI TRAVEL |
| дизайн финтех-приложения | `/fintech-interface-design` | VOLT PAY |
| дизайн мобильного приложения | `/mobile-app-design` | MIROX APP |

### 1.3 Не делать doorway-географию

Городскую страницу создавать только если выполнены все условия:

- подтверждён спрос по городу;
- есть реальный формат работы с этим городом;
- уникальны не только title и H1, но и предложение, FAQ, сроки коммуникации, кейс или локальное доказательство;
- страница включена в навигационный кластер и не конкурирует с основной услугой;
- есть план измерения по паре «городской запрос → URL».

Начинать максимум с 1–2 пилотных городов. Пятнадцать копий главной не публиковать.

## Приоритет 2: доказательства и конверсия — неделя 2–4

### 2.1 Аудит всех кейсов

Для каждого коммерчески значимого кейса проверить:

- понятна ли отрасль и тип продукта в title/H1;
- указана ли реальная задача, а не описание картинки;
- отделены ли подтверждённые результаты от предположений;
- понятна ли роль студии;
- есть ли ссылка на релевантную услугу;
- ведёт ли финальный CTA в атрибутированную форму;
- не перезаписывается ли это генератором.

### 2.2 Формы

- Сохранять только минимальные обязательные поля: имя и контакт.
- Не очищать ввод при ошибке.
- Показывать состояние отправки в кнопке и подтверждение только после backend delivery.
- Проверить клавиатуру, автозаполнение, фокус и читаемость ошибок на 320–430 px.
- Отдельно измерять `form_start`, `form_error`, `lead_delivered`.

### 2.3 Доверие

- Не использовать неподтверждённые цифры и отзывы.
- Для каждого результата хранить источник подтверждения.
- На service-page показывать 1–3 максимально релевантных кейса, а не случайную галерею.
- Объяснять первый этап, состав результата и ограничения до формы.

## Приоритет 3: контентная воронка — неделя 3–8

### 3.1 Контент строится от коммерческой страницы

На каждый приоритетный кластер — 3–5 материалов нижней и средней части воронки:

- стоимость и состав работ;
- ошибки выбора подрядчика;
- чек-лист подготовки материалов;
- сравнение подходов;
- разбор реального кейса;
- технические ограничения и интеграции.

Каждая статья должна вести на одну релевантную услугу и один кейс. Не публиковать статьи ради количества.

### 3.2 Очерёдность

1. UX/UI SaaS и B2B-системы — уже есть сильнейшая доказательная база.
2. Лендинги и редизайн — широкий спрос, но высокая конкуренция.
3. Мобильные и финтех-продукты — узкий коммерческий интент и хорошие кейсы.
4. HMI/промышленные интерфейсы — нишевый спрос, но высокая релевантность.
5. Отели и туризм — развивать только при появлении показов и региональной релевантности.

### 3.3 Редакционные требования

- один поисковый интент на страницу;
- собственные примеры и иллюстрации;
- ответ на вопрос в первых абзацах;
- реальные ограничения и критерии выбора;
- дата обновления только при содержательном изменении;
- внутренняя ссылка на услугу и кейс;
- отсутствие массовой генерации и перефразированных дублей.

## Приоритет 4: сниппеты и CTR — после первых 100–300 показов на URL

- Не переписывать title без данных.
- Искать страницы с высокой позицией и низким CTR.
- Сравнивать запрос, title, description и фактическое содержание.
- Менять один элемент за цикл и аннотировать дату.
- Оценивать минимум после достаточного количества показов, отдельно по Google и Яндексу.

## Приоритет 5: производительность — неделя 2–6

- Измерить LCP, INP и CLS на главной, трёх основных service-pages и тяжёлых кейсах.
- Сначала исправлять реальные полевые проблемы, затем лабораторные оценки.
- Для первого экрана: корректные размеры, современный формат, preload только критичного изображения.
- Для галерей: lazy-load, width/height или aspect-ratio, отсутствие загрузки всех кадров до взаимодействия.
- Ограничить стоимость анимации на слабых устройствах и при `prefers-reduced-motion`.
- Проверить кэширование статических ассетов и версионирование.

## Приоритет 6: внешняя авторитетность — неделя 4–12

Без внешних сигналов коммерческий топ маловероятен. Только легитимные действия:

- публикация подробных кейсов на профессиональных площадках со ссылкой на полный разбор;
- экспертные материалы для отраслевых медиа;
- партнёрские страницы с разработчиками и интеграторами;
- каталоги студий только с реальным профилем и одинаковыми контактами;
- выступления, подкасты, интервью и исследования с первичными данными;
- запрос ссылки у клиентов только на реально выполненный проект.

Запрещено: покупные пакеты ссылок, сетки сайтов, массовые каталоги, спам-комментарии и фиктивные отзывы.

## Рабочий ритм

### Еженедельно

1. Экспорт GSC и Вебмастера.
2. Разделение брендовых и небрендовых запросов.
3. Выбор одного барьера по максимальному ожидаемому влиянию.
4. Одна обратимая правка.
5. Локальная и production-проверка.
6. Запись deploy и метрики в `docs/organic-growth-log.md`.

### Ежемесячно

- индекс и canonical по всем коммерческим URL;
- запросы/страницы с ростом и падением;
- CTR по позиционным диапазонам;
- переходы service → case → form;
- ошибки и подтверждённые доставки;
- новые качественные домены-ссылки;
- решение: расширять кластер, улучшать текущую страницу или остановить эксперимент.

### Недели 3–4

### Недели 5–8

- развивать только страницы, которые получили индекс и показы;
- тестировать сниппеты при достаточной выборке;
- устранить подтверждённые CWV-проблемы;
- получить первые релевантные внешние упоминания.

### Недели 9–12

- оценить страницы по небрендовым кликам и подтверждённым лидам;
- объединить или удалить слабые/каннибализирующие материалы;
- масштабировать только работающие кластеры;
- запускать географический пилот только при подтверждённом спросе и уникальном локальном содержании.

## Что нельзя обещать

Нельзя гарантировать поток лидов или топ поисковиков одной технической доработкой. Можно гарантировать управляемый процесс: сайт индексируется, каждый коммерческий запрос получает релевантную страницу и доказательство, каждая заявка измеряется до доставки, а решения принимаются по данным. Именно отсутствие этого контура, а не один «неправильный метатег», сейчас является главным ограничением роста.
